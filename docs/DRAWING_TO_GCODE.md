## Распознавание по типу входа

**DXF (векторный)** — `dxfPrims` (`index.html:1266`) уже даёт отрезки/дуги/окружности. Добавить: TEXT/MTEXT (надписи), DIMENSION (значение размера и точки привязки), слои, блоки (INSERT). Нейросеть не используется.

**PDF** — сначала проверить, есть ли векторные пути и текстовые объекты (pdf.js, Apache-2.0: операторы пути + `getTextContent`). Если есть — как DXF. Если PDF — скан, растеризовать страницу и идти по ветке «фото».

**Фото / скан** — конвейер:
1. Проверка качества (резкость, освещённость, размер) — подсказка переснять.
2. Перспектива: поиск рамки листа/основной надписи (ГОСТ 2.104) → гомография.
3. Ориентация (0/90/180/270) по тексту.
4. Сегментация видов (разделение по пустым полосам и рамкам).
5. Геометрия: существующая автообводка (линии, окружности по дуговому покрытию).
6. OCR размеров: Tesseract (уже в APK) с набором символов `0-9 . , ± Ø R M x ° + -`; кириллица — PP-OCRv5 cyrillic (Apache-2.0) как кандидат.
7. Связь «размер ↔ элемент»: геометрически (выносные линии, стрелки, близость) — алгоритм; VLM — проверка и спорные случаи.
8. Масштаб: из размерных чисел (метод наименьших квадратов по нескольким размерам); противоречия — в список конфликтов.
9. Всё — в `observations`, затем подтверждение.

## Что ИИ делает и чего не делает

Делает: называет элементы («4 отв. Ø8.5 сквозн.»), читает спорные надписи, сопоставляет размер с элементом, предлагает последовательность операций, объясняет предупреждения, отвечает на вопросы.
Не делает: не считает координаты траектории, не пишет G-код напрямую, не меняет подтверждённые данные, не придумывает отсутствующие размеры и глубины.

## Первый прототип (из ТЗ §31)

Пластина с 4 отверстиями. Делается **без VLM**: DXF/PDF-векторы и фото → окружности + OCR → подтверждение → `drill` (центровка + сверление) → G-код → проверка → 3D → сохранение. Критерии — `AUDIT.md` §20. После этого тот же сценарий повторяется с включённым VLM, чтобы измерить, что он добавляет.
