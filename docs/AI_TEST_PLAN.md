# План тестирования

## Сейчас (14.11.2026)

Тесты в репозитории (`tests/`, описание — `tests/README.md`), запускаются в GitHub Actions на каждой ветке, кроме `main` (`test.yml`, без публикации). Локально: 45 тестов Playwright (Chromium) + 3 модульных (`node --test`), все проходят.

- Эталонный G-код (`tests/golden`, v2.9.2), обработчики, интерфейс, своя программа, параметрия, подвод, «Не проверено», IndexedDB.
- Чертежи: DXF (модульные), векторный PDF, фото — чистое и ухудшенное (меньше, размытие, шум, JPEG): «ничего не выдумывается».
- Сквозной сценарий «чертёж → подтверждение → центровка и сверление → G-код → проверка → 3D → исходник из проекта» для PDF и фото (`drawing-scenario.spec.js`), прототип Codex для DXF (`plate.spec.js`).
- Сборка APK/EXE без публикации (`build-check.yml`): в пакетах есть `src/`, Tesseract и pdf.js.

**Не проверено:** реальные фото и сканы; Android, iPhone, Windows на устройствах; 3D-отрисовка в локальных прогонах (заглушка).

## Уровни

| Уровень | Инструмент | Что проверяет | Где запускается |
|---|---|---|---|
| Unit | `node --test` для модулей `src/` (без зависимостей; Vitest не понадобился) | схема, валидатор, распознавание признаков, планировщик | CI на каждый push в любую ветку |
| Golden G-code | Playwright | одинаковые входы → байт-в-байт тот же G-код (8 наладок + 19 шаблонов + эталонные чертежи) | CI |
| E2E | Playwright | сценарий «По чертежу» от файла до .nc, своя программа, перевод в параметрию | CI |
| Модели | скрипт замеров | метрики `AI_MODEL_BENCHMARK.md` | вручную на устройствах |
| Android | instrumentation (androidx.test) | мост JS↔Java, загрузка модели, OOM, офлайн | эмулятор в CI + телефон владельца |
| iPhone | вручную по чек-листу | ТЗ §28 | iPhone владельца |
| Windows | вручную + smoke в CI (windows-latest) | запуск EXE, OCR, ИИ | ПК владельца |

## Эталонные чертежи (ТЗ §27)

`tests/fixtures/drawings/NN-name/`: исходники (DXF/PDF/SVG/PNG — генерируются скриптом из одного описания), `expected.json`. Есть №1; `expected-ops.json` и `expected.nc` — по мере появления.

1. Пластина с 4 отверстиями · 2. Прямоугольный карман · 3. Круглый карман · 4. Паз · 5. Контур с радиусами · 6. Несколько видов · 7. С допусками · 8. Плохое фото · 9. Противоречивые размеры (ожидается конфликт, а не «угаданный» ответ) · 10. Неподдерживаемая геометрия (ожидается `unsupported`).

## Правила

- Правдоподобная картинка — не доказательство: сравниваются числа (координаты, Ø, глубины) и G-код.
- Тест ИИ, который «прошёл» на выдуманном ответе, — провал: проверяется и отсутствие лишних элементов.
- Недоступное устройство явно пишется в отчёте как «не проверено».
