# Хранилище: переход к IndexedDB без риска для данных

Статус: **этап 1 реализован** (ветка `feature/fresa-local-ai`), `src/storage/idb.js`, тесты `tests/e2e/storage.spec.js`.

## Почему

Сейчас всё в `localStorage` (≈5 МБ на сайт): проект `fcam`, «Мои детали» `fcam_lib`, своя программа `fcam_code`/`fcam_src`, фото подложки `fcam_skimg` и др. Фото уже упирается в лимит (`index.html`, «Фото не поместилось в память»). Чертежам, PDF и моделям нужен IndexedDB.

## Правила

1. **localStorage — основное хранилище проекта, его не трогаем.** Модуль `idb.js` только читает `localStorage`; единственная запись — `restoreKey()`, и она вызывается только по явному действию пользователя (в интерфейс пока не выведена).
2. **Этап 1 — резервная копия, а не перенос.** Каждый ключ `fcam*` копируется в IndexedDB (`kv`, ключ `ls:<имя>`) с SHA-256, копия проверяется чтением. Повторный запуск копирует только изменившиеся ключи. Результат — запись `meta/ls-backup-1`.
3. **Нет IndexedDB — нет проблемы.** Если IndexedDB недоступна (приватный режим, запрет, ошибка), модуль возвращает `{ok:false, reason}`, Fresa работает как раньше.
4. **Новые данные** (исходники чертежей, фото, подтверждённая геометрия) пишутся в IndexedDB (`blobs`, `drawings`) с SHA-256 и проверкой чтением.
5. Удаление старых данных из `localStorage` — **отдельный будущий этап, только после согласия владельца** и после проверки на реальных устройствах.

## База

`fresa` v1: `kv` (резервные копии), `blobs` (файлы `{blob,type,size,sha256,name,t}`), `drawings` (чертежи `fresa.drawing/1`), `meta` (записи о миграциях).

## Когда запускается

Через 1.2 с после старта приложения (не мешает первому экрану): `import('./src/storage/idb.js')` → `backupLocalStorage()`. Результат — `window.__storeBackup`.

## Проверено автотестами

- `localStorage` до и после резервного копирования совпадает побайтно.
- Каждая копия равна исходному значению.
- Повторный запуск: 0 скопировано, все «без изменений»; после изменения одного ключа — ровно 1 скопировано.
- Без IndexedDB: приложение запускается без ошибок, G-код генерируется, `localStorage` не изменён.
- Файл: запись → чтение → совпадение SHA-256.

## Не проверено

- Safari на iPhone владельца (очистка хранилища системой, квоты) — нужен ручной тест.
- Android WebView и Windows WebView2 — проверить на устройствах после сборки (сборка без публикации — `build-check.yml`).
- Поведение при переполнении квоты IndexedDB.

## Сборка

`src/` копируется в приложение: `build.yml` (`cp -r src dist/src`) и `build-check.yml`; в Windows EXE файлы встраиваются рекурсивно (`GcodeCNC.csproj`), это же исправляет K-01 (распознавание фото в EXE).
