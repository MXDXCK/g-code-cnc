# Windows: локальный ИИ

Статус: проект (Фаза 10).

## Сейчас

`windows/Program.cs`: WinForms + WebView2, страница распаковывается в `%LOCALAPPDATA%\GcodeCNC\web`, адрес `https://app.local`. Мостов к JS, кроме навигации, нет.

**Дефект (вероятный):** `GcodeCNC.csproj` встраивает `web\*.*` и `web\lib\*.*` — не рекурсивно. Tesseract лежит в `web\lib\tesseract\` → в EXE его, скорее всего, нет, а `OCR_LOCAL=true` указывает на эти файлы → «Программа с фото» не работает. Исправление: `web\**\*.*` с сохранением пути в `LogicalName`. Проверить на Windows.

## Варианты ИИ

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| A. Ollama (MIT) | пользователь сам ставит Ollama; Fresa через мастер проверяет `http://127.0.0.1:11434` и предлагает `qwen3-vl:2b` (1.9 ГБ) [1] | просто, обновляется Ollama | отдельная установка; CORS/Origin нужно разрешить (`OLLAMA_ORIGINS=https://app.local`) |
| B. llama.cpp внутри Fresa | оболочка C# скачивает `llama-server` (MIT) и модель, запускает на 127.0.0.1 со случайным портом и токеном | без сторонней установки | размер, поддержка версий |
| C. WebGPU в WebView2 | тот же BrowserAIProvider, что для iPhone | один код | слабее нативного; [ПРЕДПОЛОЖЕНИЕ] WebGPU в WebView2 включён как в Edge — проверить |

Рекомендация: начать с A (мастер подключения, необязательный), затем B. Ollama не обязательна для браузерной версии. Сервер слушает только 127.0.0.1.
