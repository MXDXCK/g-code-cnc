## 4. Android

- WebView, страница из assets через `WebViewAssetLoader` на `https://appassets.androidplatform.net` (`MainActivity.java`). Мост `AndroidApp`: `saveFile`, `shareFile`, `platform`.
- `applicationId 'app.fresa.cnc'`, `minSdk 24`, `targetSdk 34`, версия из `version.json` (versionCode = 10000·maj + 100·min + patch) — `android/app/build.gradle`.
- Подпись: только из секретов GitHub, иначе сборка останавливается (`build.yml`). **Ключ и applicationId менять нельзя** — иначе обновление в RuStore не встанет.
- Нет NDK/JNI, нет нативных библиотек → для llama.cpp нужен новый модуль `:ai` с CMake (см. ANDROID_AI_RUNTIME.md).
- Выбор файла: `ACTION_GET_CONTENT */*` — камеры напрямую нет (через галерею/файлы). Для «сфотографировать чертёж» нужен `capture`/Intent камеры.
- Разрешения: INTERNET, WRITE_EXTERNAL_STORAGE (≤ API 28).
- `targetSdk 34`: [ПРЕДПОЛОЖЕНИЕ] требования RuStore к targetSdk не проверены; у Google Play с 2025 г. — 35. Проверить перед следующей публикацией.
- Опубликованная в RuStore версия: **2.7.1** (одобрена 10.11.2026 со слов владельца). Репозиторий — 2.9.2. Соответствие сборки RuStore тегу v2.7.1 не проверено: страница RuStore недоступна из этой среды [ОПЫТ: allowlist].

## 5. Safari / PWA (iPhone)

- `sw.js`: кэш `gcnc-v1`, страница — сеть с тайм-аутом 3 с, иначе кэш; three.js и Tesseract с CDN кэшируются при первом использовании.
- Хранилище: только `localStorage` (13 ключей `fcam*`, IndexedDB не используется — 0 вхождений). Фото подложки уже упирается в квоту (`index.html:2981`, сообщение «Фото не поместилось в память»).
- WebGPU в Safari: объявлен в iOS 26 [W3]. **Но** полевой отчёт: на iPhone 11 Pro Max (iOS 18.7/Safari 26.5) ни одна малая модель (Qwen2.5-0.5B…1.5B через WebLLM/wllama) не доработала до конца — перезагрузка вкладки или ошибка загрузки, хотя WebGPU «поддерживается» [W4]. Вывод: **наличие WebGPU ≠ возможность запустить VLM**; на iPhone обязательны реальные испытания на устройстве владельца.
- Safari может очищать хранилище сайта → модель придётся перекачивать; это надо показывать пользователю.

## 6. Windows

- .NET 8 WinForms + WebView2, страница распаковывается в `%LOCALAPPDATA%\GcodeCNC\web`, адрес `https://app.local` (`windows/Program.cs`).
- **Найден вероятный дефект:** `GcodeCNC.csproj` встраивает `web\*.*` и `web\lib\*.*` — шаблон не рекурсивный, а Tesseract лежит в `web\lib\tesseract\` → в EXE, скорее всего, **нет файлов OCR**, а `OCR_LOCAL=true` указывает на них. «Программа с фото» на Windows, вероятно, не работает. [ПРЕДПОЛОЖЕНИЕ по коду сборки; на Windows не проверено.]
- WebView2 основан на Edge/Chromium, WebGPU там доступен как в Edge [ПРЕДПОЛОЖЕНИЕ — проверить в рантайме]. Для тяжёлых моделей естественный путь — Ollama или встроенный llama.cpp (см. WINDOWS_AI.md).

## 10. Архитектура «Чертёж → G-код»

См. `DRAWING_TO_GCODE.md` и `AI_ARCHITECTURE.md`. Принцип: **сначала точные пути, ИИ — помощник**:
1. DXF → точная геометрия (уже есть) + чтение размеров из DIMENSION/TEXT (добавить).
2. PDF с векторами → pdf.js → отрезки/дуги/текст (новое).
3. Фото/скан → коррекция перспективы → автообводка (есть) + OCR размеров → **предложения**; VLM (если устройство тянет) — подписи, типы элементов, связь «размер ↔ элемент».
4. Всё распознанное — в статусе «предложено»; в CAM идёт только подтверждённое пользователем.
5. CAM — существующие OPS/генераторы; G-код — существующие постпроцессоры; проверка — `checkProgram` + 3D.

## 11. Схема геометрических данных

См. `DRAWING_SCHEMA.md`: версия `fresa.drawing/1`, четыре слоя (наблюдения ИИ/алгоритмов → подтверждённое → вычисленное → операции), у каждого элемента id, тип, геометрия, единицы, допуски, источник, уверенность, статус, связи. Подтверждённое не перезаписывается новым ответом ИИ.

## 12. План интеграции с CAM

См. `CAM_INTEGRATION.md`: отображение элементов схемы на существующие OPS (Hole → drill/tap/thread/helix, Pocket → pocketRect/Circle/Isl, Slot → slot/pocketOval, ClosedContour → contour/stock). Новые операции не придумываются: если признака нет в OPS — статус «не поддерживается», а не генерация.

## 13. План проверки G-кода

Расширить `checkProgram` (`:2220`) до трёх уровней: **Ошибка / Предупреждение / Не проверено**. Добавить: пределы осей и профили станков, модальные состояния (G90/G91, G17–19, G43/G49, G41/42/40), дуги (сходимость R/IJ), неподдерживаемые коды для выбранной стойки, глубины против толщины из чертежа. Сейчас третьего уровня нет — то, что не проверяется, просто не упоминается.

## 19. Поэтапная реализация

См. `AI_ROADMAP.md` (фазы 0–15 из ТЗ с критериями выхода). Важная поправка к порядку: **первый прототип (пластина с 4 отверстиями) делается без нейросети** — DXF/PDF/фото → окружности + OCR размеров → подтверждение → сверление. Это быстрее, проверяемо и полезно сразу всем устройствам. VLM подключается после, как улучшение распознавания (Фазы 8–10).

## 20. Критерии первого рабочего прототипа

1. «ИИ → По чертежу» открывается из меню и главного экрана.
2. Вход: DXF, PDF с векторами и фото/скан пластины с 4 отверстиями (эталоны в `tests/drawings/01-plate-4-holes/`).
3. Найдены 4 окружности; для DXF/PDF — координаты точны до 0.01 мм; для фото — ±1% до подтверждения.
4. Размерные числа (Ø, межосевые, габариты) распознаны и **привязаны** к элементам; непривязанные показаны как «не сопоставлено».
5. Пользователь подтверждает или правит каждое отверстие (Ø, X, Y, глубина = толщина + выход) — без подтверждения кнопка «Рассчитать» неактивна.
6. Создаются операции существующего CAM: центровка + сверление (`drill`, PAT `list`), инструменты подбираются из магазина или предлагаются.
7. G-код открывается во вкладке G-код, `checkProgram` без ошибок, 3D показывает 4 отверстия на нужных местах.
8. Проект сохраняется вместе с чертежом и подтверждённой геометрией (IndexedDB), экспорт .nc работает.
9. Отчёт о происхождении: что найдено алгоритмом, что OCR, что ИИ (если был), что подтверждено человеком.
10. Работает офлайн на Android и в Safari на iPhone (Lite), автотест проходит в CI.

## Неподтверждённые предположения (сводно)

- Совпадение сборки RuStore 2.7.1 с тегом v2.7.1.
- Отсутствие OCR в Windows EXE (вывод по csproj).
- Потребление ОЗУ Qwen3-VL-2B/4B на телефонах, скорость обработки изображения.
- Возможность запустить любую VLM в Safari на iPhone владельца.
- Требования RuStore к targetSdk и к загрузке моделей после установки (правила модерации не прочитаны — страница недоступна).
- Доступность Hugging Face из России в будущем.

## Противоречия в требованиях

1. **«ИИ локально на iPhone» vs реальные ограничения Safari.** Полевые данные [W4] показывают, что даже 0.5–1.5B модели могут не запуститься. Ближайшее решение: полноценный режим без ИИ (векторы + алгоритмы + OCR + редактор) и попытка малой модели только после проверки на устройстве.
2. **«Без платной инфраструктуры» vs «точное распознавание чертежей».** Опубликованные хорошие результаты — у моделей, **дообученных** на чертежах [W7][W9]. Дообучение — разовая работа на GPU (не сервер для пользователей). Бесплатные варианты (Colab/Kaggle) не проверены на доступность из РФ. Решение владельца: допускается ли разовое дообучение и на каких данных.
3. **«TypeScript» vs текущий проект без сборки.** Решение: JS + JSDoc + `tsc --checkJs` (без сборки), либо добавить esbuild в Actions.
4. **«Работать в ветке feature/…» vs текущий процесс публикации** — релизы собираются только из `main`, поэтому работа в ветке ничего не публикует; слияние в main = новая сборка и релиз на GitHub (не в RuStore).
