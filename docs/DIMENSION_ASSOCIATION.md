# Привязка размерных надписей к геометрии

Статус: работает в прототипе «По чертежу» (ветка `feature/fresa-local-ai`). Код: `src/drawing/associate.js`, подготовка фото — `src/drawing/import-raster.js`. Тесты: `tests/unit/drawing-dxf.test.mjs`, `tests/e2e/drawing-import.spec.js`, `tests/e2e/drawing-scenario.spec.js`.

## Зачем

OCR даёт только «где-то на листе написано 90». Чтобы получить координату отверстия, нужно понять, **к каким двум элементам относится это число**. Это решают правила оформления чертежей (ГОСТ 2.307), а не нейросеть: размерная линия, выносные линии, стрелки, полка-выноска. Число, которое не удалось привязать, не используется — оно показывается пользователю как «не сопоставлено».

## Вход и выход

Вход не зависит от источника: отрезки, окружности и надписи в «единицах рисунка» (мм для DXF и векторного PDF, пиксели для фото), ось Y вверх. Из DXF дополнительно приходят готовые размеры (`DIMENSION`) с точками привязки.

Выход — **наблюдения, а не решения**. Каждое значение несёт источник:

- `dimension` — получено из размерной надписи;
- `measured` — измерено по рисунку, нужно проверить.

Кроме значений выход содержит:

- список конфликтов;
- масштаб и сколько размеров его подтвердили;
- непривязанные надписи;
- контур детали;
- толщину, если она указана текстом.

## Шаги

1. **Допуск.**
   - Векторы: `max(0.02 мм, 0.05% габарита)`.
   - Фото: `max(2 пикс., 0.4% габарита)`.
2. **Контур детали.** Наибольший прямоугольник, каждая сторона которого покрыта **одной непрерывной** линией не менее чем на 97%.
   - Выносная линия, продолжающая сторону с зазором, контур не удлиняет.
   - Разрыв больше допуска перекрывается, только если его пересекает наклонная линия: это узел скелета на фото или выноска. Перпендикулярная линия (угол, выносная) поводом не считается.
   - Предпочитается прямоугольник, внутри которого лежат все окружности.
3. **Размерная линия для каждого линейного числа.** Это ближайший отрезок, который:
   - параллелен надписи (±8°);
   - лежит под ней на расстоянии 0,1–2,5 высоты шрифта;
   - имеет проекцию центра надписи в пределах отрезка.
4. **Выносные линии.** Перпендикулярные отрезки, доходящие до размерной линии.
   - Цепочка размеров на одной прямой (15 + 90) может прийти одним отрезком. Тогда участок надписи ограничивается ближайшими выносными слева и справа от неё.
   - Выносная заходит за размерную линию не дальше ~1 высоты шрифта, а осевая проходит насквозь. Это их различает.
5. **Масштаб.** Берётся только по размерам, у которых выносные стоят точно на концах участка.
   - Берётся медиана отношения «число / длина».
   - Размеры, отличающиеся больше чем на 1,5%, не участвуют, и об этом пишется заметка.
   - Для векторов без таких размеров масштаб считается 1:1.
6. **Пара выносных и ссылки.** Выбирается пара с наименьшей ошибкой длины при найденном масштабе, предпочтительно та, между которыми стоит надпись. Ошибка больше 0,2% (векторы) или 3% (фото) — это **конфликт**, а не подгонка. Каждая выносная «держит» одно из трёх:
   - центр окружности на той же оси;
   - сторону контура;
   - просто линию.
7. **Диаметры, резьбы, количество** («4 отв. Ø10», «M8», «Ø6,8»). Окружность ищется по порядку, от надёжного к ненадёжному:
   1. по выноске: обход графа отрезков на глубину 3 от полки под надписью, конец — на окружности; стороны контура выноской не считаются;
   2. по размерной линии через центр длиной ≈ 2r;
   3. ближайшая окружность — только с пониженной уверенностью (0,5).

   После этого:
   - окружности одного радиуса объединяются в группу;
   - число «4 отв.» сверяется с размером группы;
   - Ø сверяется с рисунком.

   Несовпадение в любой из этих проверок — конфликт.
8. **DIMENSION из DXF.** Точки привязки известны точно. Число сверяется с расстоянием в файле (допуск `max(0,01 мм, 0,2%)`).
9. **Координаты отверстий.** Отдельно по X и по Y:
   - окружности на одной вертикали (горизонтали) получают одну координату;
   - размеры образуют граф ограничений между узлами «сторона контура» и «колонка отверстий»;
   - значения распространяются от базы (левая/нижняя сторона = 0);
   - два пути с разным результатом — конфликт «размеры противоречат друг другу»;
   - колонка без размера получает значение `measured`;
   - если размер и рисунок расходятся (>0,05 мм у векторов, >max(0,5 мм; 3%) у фото), это тоже конфликт.

## Фото: что делается до привязки

| Этап | Как | Почему так |
|---|---|---|
| Линии | Адаптивный порог и утоньшение из автообводки Fresa (`window.__at.atLines`) | уже есть и проверено в «Чертёж 2D» |
| Склейка скелета | Кусок продолжается соседним (концы ≤ 2 пикс.), который лучше сохраняет направление (≤ 35°); на перекрёстке линия идёт прямо | трассировщик рвёт наклонные линии и окружности на «ступеньки» по 1–3 пикселя |
| Окружности | Голосование краёв по градиенту (Хаф) → проверка: чернила лежат на ≥ 75% окружности, кольцо узкое → уточнение центра по скелету | по отдельным «ступенькам» дугу не подогнать |
| Буквы «о», «0», «Ø» | Маленькое кольцо без осевой линии, выходящей за него с обеих сторон, отбрасывается (с предупреждением) | иначе буквы становятся «отверстиями» |
| Надписи | Tesseract (eng), разреженный текст, второй проход для повёрнутых на 90° | Tesseract уже встроен в APK/EXE |
| Мусор OCR | «Слова» без цифр с уверенностью < 0,85 не берутся и не закрывают линии под собой | OCR читает углы рамки как «L», «=)» |
| «Ø» | «@10», «010», «O10» → «Ø10» с пониженной уверенностью и пометкой «Ø из «@10»» | типичные ошибки OCR на знаке диаметра |

## Измерено (14.11.2026, только синтетические эталоны)

Эталон №1 `tests/fixtures/drawings/01-plate-4-holes`: пластина 120×80, 4 отв. Ø10, 6 линейных размеров, выноска «4 отв. Ø10».

| Вход | Окружности | Масштаб | Координаты | Конфликты |
|---|---|---|---|---|
| DXF (DIMENSION) | 4 из 4 | 1:1 | все 4 отверстия «по размеру», совпадают с эталоном | нет |
| Векторный PDF | 4 из 4 | 1:1 | все «по размеру», совпадают | нет |
| PNG 1600×1120 (8 пикс/мм) | 4 из 4, центр ±1,5 пикс. | 0,125 мм/пикс., 6 из 6 размеров | все «по размеру», совпадают | нет |
| То же ×0,75, размытие, шум, JPEG | 4 из 4 | по 5 размерам | часть «измерено» (OCR пропустил «90»), отклонение ≤ 0,1 мм | нет |
| То же ×0,6 | 4 из 4 | по 4 размерам | часть «измерено», ≤ 0,1 мм | нет |
| То же ×0,5 | 4 из 4 | по 3 размерам | часть «измерено», до 0,6 мм | нет |
| То же ×0,4 (шрифт ≈ 11 пикс.) | 4 из 4 | не определён | **не предлагаются** — поля пустые, вводит пользователь | нет |

**Это проверка алгоритма, а не точность на реальных чертежах.** Реальные фото и сканы владельца ещё не испытывались. Обещаний точности (например, «0,01 мм») нет до испытаний на эталонных файлах (`AI_TEST_PLAN.md`).

## Ограничения (сейчас)

- **Фото:**
  - перспектива не исправляется, снимок должен быть ровным;
  - поворот текста — только 0° и 90°.
- **OCR — только латиница и цифры** (eng). Поэтому:
  - «Толщина 10» не читается, и толщину подтверждает пользователь;
  - «отв.» угадывается по типичным ошибкам.
- **Размеры:** только горизонтальные и вертикальные линейные, плюс Ø, резьба M, количество. Угловые, радиальные для отверстий, по окружности центров (PCD) и с допусками в расчёт не идут — допуск читается, но не используется.
- **Чертёж:** один вид. Контур детали — прямоугольник.
- **Ноль:** «левый нижний угол детали на чертеже = левый нижний угол заготовки». Если заготовка с припуском или ноль другой, координаты правит пользователь.
