## Реализовано в прототипе «По чертежу»

- **D-13** Сначала сквозной сценарий для четырёх окружностей `CIRCLE` в XY (Codex, 10.11). С 14.11 — DXF, PDF и фото, от 1 до 60 окружностей, у каждой решение «сверлить» или «Не обрабатывать». Пользователь подтверждает миллиметры при отсутствии единиц в DXF, каждое отверстие и наладку. Из магазина выбираются уже настроенные центровка и сверло, а глубины и высоты задаёт пользователь. CAM получает подтверждённые координаты через существующий `drill` с `PAT list` и циклом G81. Разные глубины сверления разделяются на операции.
- **D-14** Исходный файл и его SHA-256 хранятся локально в IndexedDB. Наблюдения DXF и подтверждённые размеры записываются раздельно в данные проекта. Так проект можно открыть из .nc с подтверждённой геометрией через существующий формат экспорта.

- **D-15** Размеры привязываются к геометрии правилами оформления (ГОСТ 2.307): размерная и выносные линии, выноска, масштаб по нескольким размерам, граф цепочек от базы. Одного OCR недостаточно — непривязанное число не используется. Расхождения — конфликт, а не подгонка. Подробно — `DIMENSION_ASSOCIATION.md`. (14.11, по замечанию владельца №6)
- **D-16** Сверление не назначается по найденной окружности. Предложенные значения — только начальные значения полей с указанием источника; в план попадает лишь отверстие с отметкой «сверлить», введённой глубиной и выбранным пользователем сверлом того же Ø. (14.11, замечание №5)
- **D-17** Точность распознавания не обещается до испытаний на эталонных файлах; в документах приводятся только измеренные значения с указанием, на чём измерены. (14.11, замечание №4)
- **D-18** pdf.js 6.2.108 (Apache-2.0) встраивается в APK/EXE в `lib/pdfjs` под именами `.js` (WebView отдаёт `.mjs` с неверным типом); на сайте — с jsDelivr. (14.11)
- **D-19** Ноль для PDF/фото: «левый нижний угол детали на чертеже = левый нижний угол заготовки»; для DXF по умолчанию — начало координат файла (как у Codex), можно переключить. Пользователь видит и правит координаты. (14.11)

- **D-20** Тестовые сборки — отдельное приложение `app.fresa.cnc.test` («Fresa ТЕСТ», отладочная подпись, свои данные, без обновлений) и EXE «Fresa-TEST» (свои данные). Рабочие applicationId и ключ не меняются, ничего не публикуется. (15.11)
- **D-21** ИИ-помощник выключен по умолчанию; его ответы — только подсказки под полями, сверенные с геометрией (`src/ai/validate.js`); в поля и подтверждения ИИ ничего не пишет. Ollama — необязательна. (15.11)
- **D-22** Модель для Android/браузера выбирается только по замеру на эталонных чертежах (`ai-bench.yml`): лицензия, размер, память, время, доля прочитанных надписей, **выдуманные числа**. Если модель не лучше режима без ИИ — её не встраиваем. (15.11)
- **D-23** Без контура детали координаты не «измеряются» — пусто; контур, внутри которого нет хотя бы половины отверстий, не используется. Неверная база опаснее отсутствующей. (15.11)
- **D-25** По замеру 15.11 на 9 чертежах (`AI_MODEL_COMPARISON.md`):
  - Qwen3-VL-2B остаётся главным кандидатом: 81% надписей, 0 выдуманных чисел при чтении, габарит 9/9. Но у неё 10 неверных координат на 25, поэтому её ответ — только подсказка через проверку геометрией.
  - Qwen2.5-VL-3B исключена: исследовательская лицензия.
  - SmolVLM2 (500M и 2.2B) на чертежах бесполезны, поэтому на iPhone модели нет: там режим без ИИ.
  - Qwen3-VL-4B — только для ПК.

  Окончательный выбор для Android — после замера на телефоне. (15.11)
- **D-24** Проверка программы различает: ошибка (тревога Fanuc или заведомо неверное движение), предупреждение (зависит от станка), «не проверено». Новые проверки не дают ни одной тревоги на эталонах Fresa (тест). (15.11)

- **D-26** Фрезерование по чертежу — только существующими операциями Fresa: карман → «Карман прямоугольный», паз → «Карман овальный», окружность по выбору человека → «Карман круглый», наружный контур и сквозное окно → «Контур по элементам» (попутно, радиус фрезы считает программа), фаска → «Фаска по контуру». Новых генераторов траекторий нет, эталоны G-кода не менялись. Распознанный элемент — только геометрия: что с ним делать (фрезеровать / окно / не обрабатывать), глубину, фрезу, шаги, врезание выбирает человек; по умолчанию наружный контур «Не обрабатывать». (15.11)
- **D-27** Запрещено мастером (операция не создаётся): глубина ≥ толщины для кармана и наружного контура (деталь/дно отделятся — отрезки пока нет), несквозное «окно», R фрезы больше R угла (меньше — предупреждение), фреза шире элемента, без подтверждения врезания центром, сквозное окно без подтверждения подкладки и пробки, фаска инструментом не 90° или ≥ глубины кромки. (15.11)
- **D-28** OCR чертежа — два прохода Tesseract: основной eng (числа, Ø) и rus+eng только для русских слов. Строка русского прохода заменяет основную, лишь если числа совпали и в основной нет Ø. Причина: rus+eng лучше читает фразы (числа 68 → 81 %, слова 0 → 97 %), но на чертежах путает Ø с «2»/«9» («4 отв. 210»). PaddleOCR точнее (числа 98 %), но 85 МБ детектор + 11,7 ГБ ОЗУ на сервере и ~30 с на чертёж — не для телефона/Safari как есть. Русский словарь (~5 МБ) встраивается в APK/EXE. (15.11)
- **D-29** Свои чертежи владельца — только вне git: `tests/fixtures/private/` (в .gitignore) или папка `FRESA_PRIVATE_DIR`; unit-тест падает, если такой файл попал в git. Искусственные искажения называются `synth-*` и нигде не выдаются за фото. (15.11)
- **D-30** `main` (15.11): в `origin/main` нет содержимого, которого нет в ветке, — только merge-коммит `9397fd7`; пробное слияние (`git merge-tree`) без конфликтов. Объединение не выполнялось — только по согласованию с владельцем. (15.11)

## Предложены в аудите (ждут владельца)

- **D-03** TypeScript: новые модули на JS + JSDoc-типы + проверка `tsc --checkJs` в CI, без сборщика; `index.html` не переносим. Альтернатива — esbuild в Actions.
- **D-07** Первый прототип (пластина с 4 отверстиями) — без VLM; VLM подключается после как измеримое улучшение.
- **D-08** Qwen3-VL-2B — **кандидат** для Android/Windows, **не утверждённая модель**. Решение — только после проверки лицензии, памяти, скорости и качества на эталонах (`AI_MODEL_COMPARISON.md`, раздел «Проверка кандидата»). Исправлено 14.11 по замечанию №10.
- **D-09** Хостинг моделей: Android/Windows — GitHub Releases (+ зеркало Hugging Face); браузер — Hugging Face; везде SHA-256.
- **D-10** Хранилище: IndexedDB для чертежей, изображений и моделей; JSON проекта — как сейчас (обратная совместимость).
- **D-11** Лицензия репозитория: сейчас публичный и без LICENSE — нужно решение владельца (закрыть или выбрать лицензию).
- **D-12** Дообучение модели на чертежах ГОСТ (разовая работа на GPU, не сервер для пользователей) — допустимо ли и на каких данных.
