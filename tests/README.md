# Автотесты Fresa

Тесты не входят в приложение (не попадают в APK/EXE/сайт как функциональность) и запускаются в GitHub Actions на каждой ветке, кроме `main` (`.github/workflows/test.yml`). Workflow ничего не публикует.

## Запуск

```bash
npm install                      # @playwright/test 1.63 и three.js 0.160 (настоящий three для 3D)
npx playwright install chromium  # один раз
npx playwright test              # все тесты
```

Без npm (среда без доступа к реестру): `NODE_PATH=<глобальные node_modules> node <playwright>/cli.js test`. Если three.js не найден в `node_modules` и не задан `THREE_DIR`, вместо него подставляется заглушка `tests/fixtures/three_stub.js` — 3D-отрисовка тогда не проверяется.

Приложение отдаётся локальным сервером `tests/server.js` (http://127.0.0.1:8765), а не через `file://`: у `file://` Chromium теряет записи localStorage при быстрой перезагрузке — это давало ложные падения.

## Что проверяется

| Файл | Что |
|---|---|
| `e2e/golden.spec.js` | эталонный G-код (обычный и параметрический): 4 наладки × 2 формата + все шаблоны деталей. Любое отличие — падение |
| `e2e/handlers.spec.js` | все функции из `onclick=…` и т.п. доступны в `window` |
| `e2e/ui.spec.js` | порядок вкладок, переходы, отмена/повтор, 3D-шкала, мастер новичка |
| `e2e/own-program.spec.js` | открытая программа не пропадает (формат, язык, перезапуск), «↩ Исходный код», инструменты из кода |
| `e2e/macro-convert.spec.js` | перевод в параметрию: резание совпадает с исходным, найдены полосы |
| `e2e/lead-in.spec.js` | подвод снаружи заготовки; обычный и параметрический код дают одну траекторию |

## Эталоны G-кода

`tests/golden/*.nc` сняты с версии 2.9.2. Если генератор меняется **намеренно**: `UPDATE_GOLDEN=1 npx playwright test tests/e2e/golden.spec.js`, затем просмотреть `git diff tests/golden` и объяснить изменения в коммите.

## Данные

`fixtures/nc/` — только синтетические программы и программа, созданная самой Fresa. Рабочие программы владельца в публичный репозиторий не кладём.
